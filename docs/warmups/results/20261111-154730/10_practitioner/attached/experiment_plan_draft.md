# 실험 계획 통합 초안 — 연구자 승인 전

상태: 자문 통합용 초안. 실행 승인이나 사전등록 확정본이 아니다. 코드 작성·모델 실행·검정력 재계산은 하지 않았다.
근거: inputs/memo_linguist.md, inputs/memo_lm.md, inputs/memo_statistician.md. 아래 표본 수·시간·검정력 관련 수치는 자문 메모의 제안 또는 추정이며 results/에서 확인한 실험 결과가 아니다.

## 1. 연구 질문과 가설

잠정 연구 질문: 관계절 유형에 따른 언어모델의 처리 난이도 차이가 선행사 유정성에 따라 달라지는가?
자문 공통안을 기준으로 주어/목적어 관계절 × 유정/무정 선행사의 완전 교차 설계를 기본 논의안으로 둔다. 연구자가 이 질문과 설계를 확정해야 한다.
종속변수 후보는 임계 영역의 surprisal이다. 높은 값은 해당 모델에서 낮은 조건부 예측 가능성을 뜻하며, 인간의 처리 난이도와 동일한 것으로 해석하지 않는다.

확증 가설 후보: 관계절 유형과 유정성의 상호작용이 있다.
예측 방향: 메모에 근거가 없어 미정이다. 목적어 관계절의 비용이나 특정 유정성 조건의 방향을 임의로 넣지 않는다. 연구자가 이론적 근거와 방향을 정하거나 비방향적 가설임을 승인해야 한다.
주효과만을 목표로 바꾸는 안은 연구 질문을 바꾸므로 자동 채택하지 않는다.

## 2. 메모 간 충돌 및 미해결 쟁점

| 쟁점 | 자문 내용 | 충돌·미확인 사항 | 초안의 처리 | 결정권 |
|---|---|---|---|---|
| 표본과 목표 | 언어학: 수작업 48세트, 조건당 48문장·총 192문장. 통계: 상호작용에는 조건당 최소 64문항, 주효과에는 32문항 제안 | 48세트의 검정력이 약 .60이라는 추정의 효과 크기·분산·유의수준·모형 근거가 없음. 세트와 문항의 단위도 확정 필요 | 어느 수치도 충분한 표본의 근거로 확정하지 않음. 가정 명시 및 모의 검정력 분석을 승인 전 보완 과제로 둠 | 연구자 |

## 3. 데이터·자극 및 교란 통제

언어학 자문의 수작업 자극을 출발안으로 기록하되, 실제 자극 파일과 적합성은 확인하지 못했다. 자동 생성 자극은 채택하지 않은 대안으로 남긴다.
각 세트는 동일한 비교 단위를 이루는 조건별 문장을 포함해야 한다. item_id, 조건, 원문, 임계 영역의 문자 경계, spillover 경계, 검수 이력을 기록한다.
대상 언어·관계절의 구조적 정의·유정성 조작 대상은 메모만으로 확정할 수 없다. 특히 한국어 실험인지 확인해야 한다.

실행 전 점검안:
- 자연스러움, 의미·화용 타당성, 동사 논항구조, 어순 및 구조적 차이, 어휘·형태소 빈도와 문장 길이를 조건별로 검토한다.
- 모델별 토크나이저로 임계 영역과 전체 문장의 토큰 수, 서브워드 경계, 형태소 분절 가능성을 확인한다. 문자 영역과 토큰 경계가 어긋날 때의 점수 귀속 규칙도 고정한다.
- 어휘 교체나 자극 제외는 승인된 기준을 적용하고 이력을 남긴다. 결과를 본 뒤 유리한 문항만 고르지 않는다.
- 토큰 수 차이가 조건과 거의 겹치면 공변량 보정만으로 효과를 식별할 수 있는지 재검토하고 실행을 보류한다.

## 4. 조건·모델·시드

조건: 관계절 유형 × 선행사 유정성의 완전 교차가 기본 논의안이며 승인 전이다.
표본: 48세트 유지와 64세트 확대는 병렬 대안이다. 독립 단위는 세트인지 확인하고, 세트 내 조건별 문장을 독립 표본으로 세지 않는다.
모델: LM 자문의 모델 3종 비교 희망을 기록한다. 모델 ID·리비전·파라미터 수·학습 데이터 정보·라이선스·토크나이저·프롬프트·캐시 유무는 미정이다.
시드: 추론은 eval 모드와 결정적 teacher-forcing 점수 산출을 우선 제안한다. 확률적 학습·추론이 있으면 기본 3개 이상의 시드와 시드 간 평균·변동 보고를 계획에 넣어 승인받는다. 시드 값은 실행 전 고정한다. 부트스트랩·검정력 모의실험의 시드도 별도로 고정한다.

## 5. 지표와 통계 분석 계획 후보

아래는 통합 제안이지 확정된 분석 계획이 아니다.

주지표 후보: 관계절 동사 영역의 토큰별 음의 로그 조건부 확률 합. 로그 밑과 단위는 실행 전 고정한다.
보조 지표 후보: 바로 다음 단어의 surprisal을 별도로 산출한다. 동사와 spillover의 합을 확증 지표로 바꾸려면 실행 전에 승인받는다.
토큰 수 정규화 값은 원래 합산 surprisal과 추정 대상이 다르므로 자동 대체하지 않는다.

분석 모형 후보: 모델별로 관계절 유형·유정성·두 요인의 상호작용을 고정효과로 두고, 세트별 임의절편과 설계가 허용하는 세트 내 임의기울기를 포함하는 혼합효과모형을 사용한다. 토큰 수 공변량의 사용 여부·함수형·중심화 방식은 진단 후 승인 전에 고정한다. 소수의 선정 모델을 임의효과 모집단 표본처럼 취급하지 않는다.

검정 후보: 사전 지정한 상호작용 계수에 대한 양측 Wald 검정. 방향 가설을 정하더라도 단측 전환은 별도 사전 승인이 필요하다. 코딩 방식·추정법·유의수준과 수렴 실패 시 처리 순서를 실행 전에 확정한다. 결과를 보고 임의효과 구조를 편의적으로 바꾸지 않는다.

다중비교 후보: 모델별 확증 상호작용 검정을 하나의 검정군으로 묶어 Holm 보정을 적용한다. 모델 간 차이의 직접 검정은 이 분석과 별개이며, 필요하면 별도의 사전 계획을 둔다. 한 모델만 유의하다는 이유로 모델 간 효과가 다르다고 결론 내리지 않는다.

효과 크기·불확실성: 조건별 추정값과 상호작용의 차이의 차이를 원래 surprisal 단위로 보고한다. 세트를 복원추출하고 세트 내 조건을 함께 보존하는 부트스트랩 신뢰구간을 제안한다. 신뢰수준·반복 횟수·시드 및 재적합 실패 처리 규칙은 미정이다.

검정력: 통계 자문의 표본 권고를 보장된 최소치로 취급하지 않는다. 예상 상호작용 효과, 세트 간 분산, 잔차, 토큰 수 분포, 다중비교와 실제 모형을 반영한 모의실험 설계가 먼저 필요하다.

제외 기준: 빈 입력, 영역 정렬 실패, 비유한 점수, 모델 길이 한도 초과 등 기술 실패의 처리와 세트 전체 제외 여부를 실행 전에 정한다. 조건별 실패율과 제외 전후 분모를 남긴다. 큰 surprisal이라는 이유만으로 제외하지 않는다.

## 6. 해석 기준 후보

- 승인된 방향 가설이 있는 경우, 상호작용의 방향·효과 크기·신뢰구간·보정 검정을 함께 보고 지지 여부를 판단한다. 정확한 판단 기준은 승인 시 고정한다.
- 비유의 결과는 효과 부재나 가설 기각의 확정 증거로 쓰지 않는다. 효과 부재를 주장하려면 최소 관심 효과와 동등성 검정 등을 별도로 사전 지정해야 한다.
- 토큰화와 언어적 조건이 분리되지 않거나 기술 실패가 편중되면 해석 제한을 명시한다.
- 모델 크기·학습 데이터·토크나이저·프롬프트 차이는 비교표와 한계에 적는다. 학습 데이터 중복·오염 가능성은 확인 범위를 밝힌다.
- surprisal의 조건 차이를 곧바로 인간과 동일한 인지 기제나 인과적 표상의 증거로 쓰지 않는다.

## 7. 개발자에게 전달할 구현 요구사항 후보

- 승인된 자극·설정·모델 리비전을 고정하고 결과 점수를 보기 전에 영역 정렬과 점수 산출을 테스트한다.
- 결과 CSV에 item_id, 조건, model_id, seed, 원문 식별자, 영역, 영역 토큰 수, 합산 surprisal, 상태·실패 사유를 남긴다. 토큰별 점수와 경계 대응도 results/에 저장한다.
- 모델 간 입력 형식, 특수 토큰, 문장 시작 처리, 문맥 범위, truncation 금지 또는 처리 규칙을 명시한다.
- results/run_manifest.json은 code/lab_utils.py의 write_manifest로 기록한다. 함수와 인터페이스는 개발자가 확인한다. 명령, 버전, 모델·토크나이저 리비전, 시드, 데이터 체크섬, 장치, 시간, 실패 내역을 보존한다.
- smoke test와 본 실행은 승인된 명령만 사용한다. 재시작 시 중복 결과를 만들지 않게 하고 원자료를 덮어쓰지 않는다.
- 분석 산출물·표·그림은 results/의 원자료에서 재생성 가능해야 한다.

## 8. 시간·자원·실행 명령

예상 실행 시간: 확인하지 못함. LM 자문의 60분·모델당 약 200문장 추정은 실제 벤치마크가 아니다. 점수 산출 외 자극 검수, 토큰화 점검, 모형 적합과 부트스트랩 비용도 확인해야 한다.
기본 실행 후보는 네트워크 없는 CPU 샌드박스다. 모델 캐시와 라이브러리 가용성은 확인하지 못했다.
needs_network: 미정. 다운로드가 필요하면 true로 선언하여 승인받아야 한다.
needs_host_accel: 기본 제안은 false. 호스트 실행이나 MPS 사용으로 바꾸려면 사전 승인이 필요하다.
run_commands: []
현재는 코드·진입점·입출력 경로가 없으므로 정확한 명령을 만들지 않았다. 실행 가능한 계획으로 승인받기 전에 smoke test와 본 실행의 정확한 명령 문자열을 반드시 채워야 한다. 빈 목록은 임의 명령 실행 허가가 아니다.

## 9. 내가 정리한 것과 연구자가 정할 것

### 내가 정리한 것 — 문서화·절차상의 결정
- 세 메모의 출처와 수치의 미검증 상태를 구분했다.
- 충돌하는 방법을 몰래 절충하지 않고 대안과 결정 대기 항목으로 남겼다.
- 확증·탐색 분석, 원자료·실행 기록·실패 기록의 구분을 명세에 넣었다.
- 실행은 하지 않았고 실험 설정을 확정하지 않았다.

### 내가 제안했지만 아직 채택하지 않은 것
- 동사를 확증 영역, spillover를 별도 탐색 영역으로 분리하는 안.
- 모델별 혼합효과모형, 모델별 상호작용 검정군의 Holm 보정, 세트 단위 부트스트랩.
- 결정적 teacher-forcing 점수 산출과 네트워크 없는 CPU 샌드박스 우선안.

### 다음 결정 — 연구자 승인 필요
- 연구 질문: 유정성과의 상호작용을 유지할지, 주효과 질문으로 바꿀지.
- 가설 방향과 이론적 근거, 대상 언어·자극의 구조적 정의.
- 표본: 검정력 근거를 보완한 뒤 48세트·64세트 또는 별도 설계를 선택할지.
- 모델: 비교 대상과 리비전, 모델 3종 유지 여부, 허용 자원.
- 토큰 수: 의미 타당성 보존 아래 어떤 매칭·공변량·설계 수정 원칙을 쓸지.
- 확증 영역, 검정군, 모형, 신뢰구간·검정력 설정, 제외·실패 처리 규칙.
- smoke test 범위, 실행 시간 상한, 다운로드·호스트 사용 필요 여부, 정확한 run_commands.

## 10. 한계와 계획 이탈

원문 자극, 모델 설정, 구현, 과거 실험은 확인하지 못했다. 이번 문서는 제공된 자문 메모의 통합에 한정된다.
승인된 plan.md가 제공되지 않았으므로 승인 계획 대비 이탈 여부는 판단할 수 없다. 이번 의뢰에서는 실험을 실행하거나 설정을 변경하지 않았다.
