# 워밍업 의뢰 키트

에이전트 학습 겸 테스트용 #의뢰 10건. 역할마다 `의뢰문.md`(디스코드에 붙여 넣을 글)와 첨부 파일이 있고, 정답과 채점 기준은 `_answer_keys/`에 있다.
자료는 모두 합성이며 `_build/make_warmups.py`(seed 고정)로 다시 만들 수 있다.

## 진행
맥에서 `cd ~/research-lab && .venv/bin/python scripts/run_warmups.py [번호...]` 한 번이면 실행, 결과 저장, 자동 채점, #성능고도화 보고까지 끝난다.
1. 결과는 `results/<시각>/`에 저장된다(응답 원문, 도구 기록, 첨부 산출물, 실행 로그).
2. 자동 채점 결과는 `results/<시각>/grading.md`. 수치·키워드·산출물 기준이며, ❔ 항목은 `_answer_keys/` 채점표로 사람이 확인해 `채점기록.md`에 적는다.
3. 보고는 `knowledge/learning_reports/pending/`에 들어가고 가동 중인 연구실이 1분 주기로 각 봇 이름으로 올린다. 연구실장 요약 1건 + 역할별 1건.
4. 다시 돌리지 않고 채점·보고만 하려면 `--regrade docs/warmups/results/<시각>`, 보고를 빼려면 `--no-report`.
5. 디스코드 수신 경로(분류 후 전달, 첨부 업로드)까지 보려면 `의뢰문.md`를 #의뢰에 직접 올린다. 이 경우 채점과 보고는 수동이다.

## 권장 순서
06 → 07 → 09 (첨부·실행·산출물 첨부 경로 확인) → 01 (분류) → 05 → 08 → 10 → 02 → 03 → 04

## 주의
- `_answer_keys/`는 에이전트에게 첨부하지 말고, `ADHOC_READ_DIRS`에 이 폴더(docs/warmups)를 넣지 않는다
- 10번의 자문 메모 3개는 시험용으로 지어낸 가상 메모이고, 그 안의 수치(검정력, 연산 한도)도 가상이다
- 같은 날 같은 역할의 의뢰는 작업 폴더를 이어 쓰므로, 같은 의뢰를 다시 시험할 때는 앞선 산출물이 남아 있다는 점을 감안한다
- 학습·테스트 결과 보고는 #성능고도화에만 올린다
