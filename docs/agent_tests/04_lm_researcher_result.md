## 언어모델 자문

### 모델 추천

로컬 맥북 실행 + 한국어 성능을 동시에 만족하는 모델을 우선순위로 정리합니다.

| 순위 | 모델 | 크기 | 한국어 성능 | 추천 근거 |
|------|------|------|------------|----------|
| **1 (주 모델)** | **EXAONE 3.0 7.8B** | 7.8B | 상 | LG AI Research의 한국어 특화 학습, autoregressive 구조로 surprisal 직접 계산 가능, Ollama 지원(GGUF 형식 제공), 한국어 토크나이저가 어절·조사 분절에 최적화되어 있어 subword→어절 집계 시 오류 최소화 |
| **2 (비교 모델)** | **Qwen 2.5 7B** | 7B | 중상 | 다국어 학습 비율에서 한국어가 상대적으로 높음, EXAONE과의 비교를 통해 한국어 특화 학습의 효과를 확인 가능, Ollama 네이티브 지원 |
| **3 (대조군)** | **LLaMA 3.1 8B** | 8B | 중 | 한국어 학습 비율이 낮은 대조군 — 한국어 특화 학습이 관계절 처리 패턴에 미치는 영향을 분리할 수 있음 |

**모델 수 권장**: 최소 2개(EXAONE + Qwen 또는 LLaMA). 모델 1개만으로는 "LLM의 패턴"이 아닌 "특정 모델의 패턴"에 불과하므로, 일반화를 위해 복수 모델 비교를 강력히 권장합니다.

**Masked LM(KoBERT 등) 비권장 사유**: surprisal의 표준 정의 S(wᵢ) = −log₂ P(wᵢ | w₁…wᵢ₋₁)는 좌-우 문맥만 사용하는 autoregressive 모델에서 직접 계산됩니다. Masked LM은 양방향 문맥을 쓰므로 pseudo-log-likelihood(PLL) 근사가 필요하고, 이는 인간의 증분적(incremental) 읽기 처리와의 대응이 이론적으로 약합니다. 다만 PLL 결과를 보조 분석으로 포함하는 것은 가능합니다.

### 측정 지표 설계

#### 주 지표: 토큰별 Surprisal → 어절별 집계

```
S(wᵢ) = −log₂ P(wᵢ | w₁, w₂, …, wᵢ₋₁)    [단위: bits]
```

**계산 절차**:
1. 문장을 모델 토크나이저로 토큰화
2. 각 토큰의 조건부 확률 → surprisal 계산 (autoregressive forward pass)
3. **Subword → 어절 집계**: 같은 어절에 속하는 subword 토큰의 surprisal을 **합산** (평균 아님!)
   - 이론적 근거: P(어절) = ∏ P(subword_j) → −log₂ P(어절) = Σ (−log₂ P(subword_j))
   - 주의: 토크나이저마다 어절 경계 표시 방식이 다름 (▁, ##, Ġ 등) — 모델별 매핑 함수 필요

4. **영역(region) 집계**: 인간 읽기시간 비교를 위해 관심 영역별로 surprisal 집계
   - 관심 영역: 관계절 동사, 관계절 내 명사구, 주절 동사, 주절 주어 (인지과학 연구원과 협의)
   - Spillover 영역: 관심 영역 직후 1-2 어절도 측정 (처리 비용이 다음 영역으로 넘치는 현상)

#### 보조 지표

| 지표 | 계산 | 용도 |
|------|------|------|
| 문장 PPL | exp(−1/N Σ log P(wᵢ\|ctx)) | 조건 간 전체 난이도 비교 |
| 엔트로피(H) | −Σ P(v) log₂ P(v) at position i | 예측 불확실성 — 관계절 유형에 따라 다음 토큰 예측이 더 불확실한지 |
| Attention 패턴 | head별·layer별 attention weight | 탐색적 분석 — 관계절 핵어·공백 위치에 대한 주의 패턴 시각화 (해석에 주의 필요) |

#### 실행 환경
```
# Ollama 기반 (권장 — 설치·서빙 간편)
ollama pull exaone3:7.8b-q4_K_M
ollama pull qwen2.5:7b-q4_K_M

# 또는 HuggingFace Transformers (surprisal 직접 계산 시)
# pip install torch transformers
# MPS 백엔드: device="mps"
```

**Ollama vs HuggingFace 선택**:
- Ollama: 모델 관리 편리, OpenAI 호환 API로 확률값 접근 가능 (`/api/generate`의 `logprobs` 파라미터)
- HuggingFace Transformers: logits에 직접 접근 → surprisal 계산이 더 정밀, 어텐션 추출 가능
- **이 실험에서는 HuggingFace 권장**: token-level logits 직접 접근이 필요하고, attention 분석도 보조적으로 할 가능성이 있으므로

### 모델 해석 가이드

#### 1. 토크나이저 효과 (가장 중요한 주의점)
각 모델의 토크나이저가 한국어를 분절하는 방식이 다릅니다. 같은 어절 "먹었던"이라도:
- EXAONE: `먹`, `었`, `던` (형태소에 가까운 분절)
- LLaMA: `먹었`, `던` 또는 `먹`, `었던` (비일관적 분절)
- Qwen: `먹었던` (한 토큰) 또는 `먹`, `었던`

**이것이 중요한 이유**: subword 수가 다르면 합산 surprisal이 달라집니다. 관계절 동사 영역에서 모델 A는 3 subword, 모델 B는 1 subword로 처리하면, 합산 surprisal은 단순 비교가 불가합니다.

**대응 방안**:
- 모델 간 비교 시: **조건 간 차이(Δsurprisal = S_대격RC − S_주격RC)**를 비교 (절대값이 아닌 상대적 패턴)
- 인간 데이터와 비교 시: surprisal 자체가 아닌 **조건 간 방향성과 효과크기 패턴**에 초점
- 각 모델의 토큰 분절 결과를 결과 파일에 기록하여 투명성 확보

#### 2. 한국어 학습 데이터 비율
- EXAONE: 한국어 비율 높음 → 한국어 구문에 대한 '경험'이 풍부, surprisal이 전반적으로 낮을 수 있음
- LLaMA: 한국어 비율 낮음 → 한국어 자체에 대한 surprisal이 높아 조건 간 차이가 묻힐 위험
- **해석 시**: 전반적 surprisal 수준과 조건 간 차이를 분리해서 보고

#### 3. 인간 읽기시간과의 대응 한계
- LLM surprisal은 증분적(incremental) 예측에 기반하므로 인간의 온라인 처리와 개념적으로 대응
- 그러나: LLM은 작업기억 제약이 없고, 되돌아 읽기(regression)가 불가하며, 전체 학습 데이터를 한 번에 학습함
- **따라서**: surprisal 패턴의 방향이 일치한다고 해서 처리 메커니즘이 같다고 주장할 수 없음 (Marr의 계산 수준에서의 유사성일 뿐)

#### 4. 프롬프트/컨텍스트 효과
- Surprisal 계산 시 문장 앞에 주는 컨텍스트(없음 vs 지시문 vs 이전 문장)에 따라 결과가 달라질 수 있음
- **권장**: 각 문장을 독립적으로, 컨텍스트 없이 입력 (인간 SPR 실험에서 문장을 개별 제시하는 것과 대응)

#### 잠재적 위험
1. **토크나이저-어절 매핑 오류**: subword → 어절 경계 매핑이 틀리면 surprisal이 잘못 집계됨. 반드시 수동 검증 필요 (최소 10문장)
2. **양자화에 의한 확률 왜곡**: Q4 양자화는 logit 분포를 미세하게 변형시킬 수 있음. 핵심 결과는 Q8 또는 fp16으로 재현성 확인 권장
3. **모델 버전 차이**: Ollama에서 제공하는 GGUF와 HuggingFace 원본의 미세한 차이 가능. 어느 소스를 사용했는지 기록 필수
4. **EXAONE 라이선스**: 연구 용도 사용 가능 여부 확인 필요 (AI EXAONE 라이선스는 비상업 연구 허용이나, 최신 조건 재확인)

> **요약**: EXAONE 3.0 7.8B(주) + Qwen 2.5 7B(비교)를 Q4_K_M 양자화로 로컬 실행. HuggingFace Transformers로 token-level surprisal 계산 후 어절 단위 합산. 80문장 기준 모델당 5분 내외. 모델 간 비교는 절대 surprisal이 아닌 조건 간 차이 패턴으로.
