# 연구실 (Research Lab)

언어인지과학 기반의 AI·언어모델·언어학·모델 학습 연구를 위한 **멀티 에이전트 연구실**입니다.
맥북에 상주하면서 디스코드로 실험을 받고, 전문 에이전트들이 역할을 나눠 끝까지 수행한 뒤 결과와 산출물을 보고합니다.
진행 상황이나 결과에 대한 질문도 디스코드에서 바로 할 수 있습니다.

## 구성원

| | 역할 | 맡는 일 |
|---|---|---|
| 🎙️ | **연구실장** | 디스코드 창구. 요청서 정리·접수, 진행 질의 응답, 중단·재개. (승인은 대신하지 않음) |
| 🗣️ | 언어학 전문가 | 자극·현상 정의·교란(길이, 빈도, 형태소, 토큰화) 점검, 언어학적 해석 |
| 🧠 | 인지·뇌과학 연구원 | 연결가설, 인간 데이터와의 대응, 인지과학적 해석의 한계 |
| 🤖 | 언어모델 연구원 | 모델·학습·평가 설계, 연산 자원 현실성, 모델 쪽 해석 |
| 🔧 | 실험 실무 담당 | 자문을 통합한 계획 수립, 구현된 코드의 실행, 결과 파일 생성 |
| 🛠️ | 백엔드 개발자 | 코드 설계·구현·테스트, 결과 **전체**를 대상으로 한 분석 파이프라인 |
| 📝 | 서류화·보고 담당 | 전체 내용을 보고서로 정리(결과 파일에 없는 숫자는 쓰지 않음) |
| ✅ | 검증 테스트 담당 | 핵심 수치를 원자료에서 **직접 재계산**, 코드 테스트, 계획 준수·주장 범위 점검 |

## 한 실험이 흐르는 순서

```
요청 접수(연구실장)
 → 전문가 자문: 언어학 · 인지과학 · 언어모델 (병렬, 메모 작성)
 → 계획 통합(실험 실무)  ── 네트워크·호스트 실행·장시간이면 ──▶ 🔐 연구자 승인(버튼)
 → 구현(백엔드 개발자)
 → 실행(실험 실무)        ── 실행 실패 시 개발자에게 1회 되돌려 수정
 → 전체 분석(백엔드 개발자)
 → 전문가 해석: 언어학 · 인지과학 · 언어모델 (병렬)
 → 보고서(서류화) ⇄ 검증(테스트 담당)   지적은 담당자에게 되돌려 수정, 최대 2회
 → 완료 보고(스레드 + #results-산출물 채널, 보고서 첨부) → 연구노트 기록 + git 커밋
```
단계마다 "누가 무엇을 했는지"가 실험 스레드에 올라옵니다. 검증에서 해결되지 않은 지적이 남으면 **숨기지 않고** 보고서 끝과 완료 메시지에 그대로 표시합니다.

## 설치 (맥북, 처음 한 번)

```bash
cd research-lab
./setup.sh                    # 파이썬 환경, colima 점검, 샌드박스 이미지(선택)
# 맥 GPU(MPS)로 돌려야 하는 실험도 허용하려면: ./setup.sh --with-host-env
```
그다음 `.env`를 채웁니다.

### 디스코드 봇 만들기
1. https://discord.com/developers/applications → **New Application**
2. **Bot** 탭 → **Reset Token** → 토큰을 `.env`의 `DISCORD_TOKEN`에. 같은 탭에서 **Message Content Intent**를 켠다(필수).
3. **OAuth2 → URL Generator**: Scopes `bot`, `applications.commands` / Bot Permissions: View Channels, Send Messages, Send Messages in Threads, Create Public Threads, Manage Threads, Attach Files, Read Message History, Manage Channels(채널 자동 생성용, 선택). 생성된 URL로 내 서버에 초대.
4. 디스코드 설정 → 고급 → **개발자 모드** 켜기 → 내 프로필 우클릭 → **ID 복사** → `DISCORD_OWNER_ID`. 서버 아이콘 우클릭 → ID 복사 → `DISCORD_GUILD_ID`.

### 모델 준비 (과금 없는 구성)
API 키는 쓰지 않습니다. 맥 터미널에서 쓸 백엔드를 한 번씩 로그인해 두면 됩니다. 없는 백엔드는 자동으로 건너뜁니다.

| 백엔드 | 준비 | 비고 |
|---|---|---|
| `claude` | `npm i -g @anthropic-ai/claude-code` 후 `claude` 실행해 구독 로그인 | 토큰 과금 없음, 플랜 한도 안에서 동작 |
| `codex` | `npm i -g @openai/codex` 후 `codex login` | ChatGPT 구독 로그인 |
| `gemini` | `npm i -g @google/gemini-cli` 후 `gemini` 실행해 Google 로그인 | |
| `local` | `brew install ollama` → `ollama serve` → `ollama pull <모델>` → `.env`의 `LOCAL_MODEL` | 완전 무료. 도구 호출을 지원하는 모델(Qwen3 계열 등)을 고르세요. `OLLAMA_CONTEXT_LENGTH=32768` 이상 권장(기본값이 짧으면 긴 대화가 조용히 잘립니다) |

역할마다 우선순위 목록(`ROUTE_*`)이 있고, 앞 백엔드가 막히면(한도 소진·로그인 풀림·서버 꺼짐) 다음으로 자동 전환합니다. 모두 막히면 실험을 일시정지하고 디스코드로 알립니다(`/resume`으로 이어감).
기본 배치: 연구실장·전문가·검증은 Claude, 개발은 Codex 우선, 실험 실무·서류화는 로컬 우선. 검증을 다른 계열 모델이 맡게 되는 경우(전환 시)는 오히려 교차 검증에 유리합니다.
CLI를 부를 때는 `*_API_KEY` 환경변수를 지워서 실수로 API 과금 경로로 가는 일을 막습니다(`KEEP_API_KEYS=1`로 끌 수 있음).

```bash
.venv/bin/python -m lab.main --check     # 모델 백엔드(실제 호출), 디스코드 토큰, 도커, 이미지 점검
scripts/service.sh install               # 상주 서비스 등록 (로그인하면 자동 시작, 죽으면 재시작)
scripts/service.sh logs                  # 로그 보기
```
디스코드 `#봇점검`에 "🟢 연구실 가동"이 올라오면 끝입니다. `#실험진행`, `#성능고도화`, `#봇점검`, `#results-산출물` 채널은 없으면 봇이 만듭니다.

## 쓰는 법

- **실험 맡기기:** `#실험진행`에 말하듯 쓰세요. 예: "GPT-2 계열 모델 크기별로 한국어 최소대립쌍 문법성 판단 정확도를 비교해줘. 데이터는 첨부." 연구실장이 요청서(`templates/request_template.md` 형식)로 정리해 보여 주고, 확인하면 접수합니다. "알아서 진행해"라고 하면 바로 접수합니다. 데이터 파일은 메시지에 **첨부**하면 `/data/uploads/`에 저장되어 실험에서 읽을 수 있습니다.
- **스레드가 실험 하나입니다.** 접수되면 그 스레드에 진행 상황이 올라오고, 같은 스레드에서 "지금 어디까지 했어?", "언어학 전문가는 뭐라고 했어?", "왜 실패했어?", "결과 표 보여줘" 같은 질문에 답합니다. 답은 실제 파일과 기록을 읽어서 합니다.
- **승인:** 네트워크(모델·데이터 다운로드), 맥에서 직접 실행(MPS), 예상 60분 초과 실험은 계획 후 멈추고 스레드에 ✅/🚫 버튼이 뜹니다. 승인은 **연구자 본인만, 버튼이나 `/approve`로만** 가능합니다. 연구실장도 대신 승인하지 못합니다.
- **명령:** `/status [EXP-###]` `/stop` `/resume` `/priority` `/report` `/approve` `/reject` `/help`
- **여러 실험:** 접수 순서(우선순위 지정 가능)대로 대기열에서 처리합니다. 노트북 부담을 고려해 기본은 한 번에 1건입니다(`MAX_CONCURRENT`).

## 폴더

```
workspace/                  (실행하면 생김, git 에는 안 올라감)
  ledger.db                 실험 대장
  notebook/                 완료된 실험의 요약. 이후 실험이 과거 결과를 검색해 참고
  experiments/EXP-###/      request.md plan.md code/ results/ logs/ report/ review/ notes/
  data/                     공유 데이터(읽기 전용으로 마운트) + uploads/
  hf_cache/                 모델 캐시(유지됨)
  host-venv/                (선택) 맥 GPU 실험용 파이썬 환경
```
`workspace/`는 자체 git 저장소로 완료 시마다 자동 커밋됩니다. 원격 백업은 직접 `git remote add`로 연결하세요.

## 안전장치

- 에이전트가 쓴 코드는 **도커 컨테이너**에서 실행됩니다: 기본 **네트워크 차단**, 실험 폴더만 쓰기 가능, 데이터는 읽기 전용, CPU·메모리 상한.
- 명령은 `DISCORD_OWNER_ID`의 사용자만 내릴 수 있고, 설정이 없으면 봇이 시작하지 않습니다.
- 파일 도구는 자기 실험 폴더 밖을 읽거나 쓸 수 없고, 역할마다 쓸 수 있는 폴더가 다릅니다(예: 서류화 담당의 `write_file`은 `results/`에 쓸 수 없고, 검증 담당은 `review/`만 씁니다). 다만 코드 실행(`run_command`)은 실험 폴더 안에서는 경로 제한이 없으므로, 수치가 맞는지는 폴더 권한이 아니라 **검증 담당의 재계산**이 지킵니다. 도커 모드에서는 컨테이너가 보는 범위(해당 실험 폴더, 읽기 전용 데이터, 모델 캐시) 밖은 애초에 접근할 수 없습니다.
- 데이터·파일·웹 안의 지시문은 명령으로 취급하지 않도록 모든 에이전트에게 규칙(`LAB_RULES.md`)으로 못박았습니다.
- 실험 1건당 토큰 상한(`TOKEN_BUDGET_PER_EXPERIMENT`)을 넘으면 **일시정지**하고 알립니다. 처음에는 낮게 잡고 실제 사용량을 보며 조정하세요.
- ⚠️ `host` 실행(맥에서 직접)은 격리가 없고 연구자 계정 권한으로 돕니다. 계획을 읽고 승인할 때 이 점을 기억하세요.

## 알아 둘 점

- **도커는 맥 GPU(MPS)를 쓰지 못합니다.** 컨테이너 안은 CPU 전용이라, 모델 규모가 큰 실험은 계획 단계에서 작은 모델·표본으로 설계되거나 호스트 실행 승인을 요청합니다.
- **colima 기본 VM은 2CPU/2GB**라 모델 실험에 모자랍니다. `setup.sh`가 맥 사양에 맞춰 시작하고, `--check`가 크기를 점검합니다.
- 노트북 덮개를 닫으면 맥이 잠듭니다. 서비스는 `caffeinate`로 유휴 잠자기를 막지만(전원 연결 시 시스템 잠자기도 막음), **덮개를 닫은 채로 돌리려면 외부 모니터+전원 연결(클램셸 모드)** 이 필요합니다. 재부팅·재시작 후에는 진행 중이던 실험이 대기열로 복구되어 이어집니다.
- **구독 한도:** 구독 로그인(claude/codex/gemini)은 토큰 과금이 없는 대신 각 플랜의 사용 한도 안에서 돕니다. 멀티에이전트는 호출이 많아 한도를 빨리 쓸 수 있어, 막히면 다음 백엔드로 넘어가고 모두 막히면 실험을 일시정지합니다. 현재 호출 누적은 `/status`에 나옵니다. 각 회사의 이용약관·한도 정책은 바뀔 수 있으니 본인 계정 기준으로 확인하세요(공식 CLI를 본인 맥에서 개인 용도로 돌리는 구성입니다).
- **CLI는 '한 턴짜리 모델'로만 씁니다:** 내장 도구(셸·파일)는 끄거나 읽기전용으로 두고, 도구 호출은 텍스트 규약(`<tool_call>`)으로 주고받아 연구실의 권한·샌드박스를 그대로 거칩니다. codex는 `--sandbox read-only`, gemini는 `--approval-mode plan`으로 내장 도구를 막지만, 읽기전용이어도 파일을 읽을 수는 있으므로 민감한 파일이 있는 계정/폴더에서는 주의하세요.
- **CLI 로그인 보관:** Claude CLI는 맥 키체인에 로그인 정보를 둡니다. 처음에는 터미널에서 `--check`를 직접 돌려 키체인 접근 팝업이 뜨면 "항상 허용"을 눌러 두세요(상주 서비스에서는 팝업을 누를 수 없습니다).
- **전환 시 교차 검증 효과:** 같은 실험의 구현과 검증이 서로 다른 모델 계열로 넘어가면 오류를 더 잘 잡을 수 있지만, 모델마다 말투·도구 호출 습관이 달라 보고서 문체가 달라질 수 있습니다.
- **로컬 모델 품질:** 도구 호출과 긴 컨텍스트를 안정적으로 다루는 모델만 실무·서류화에 맞습니다. `--check`를 통과해도 품질은 별개이니 첫 실험의 보고서를 직접 확인하세요.
- **맥 개인정보 보호(TCC) 주의:** 이 폴더가 `~/Documents`, `~/Desktop`, `~/Downloads` 아래에 있으면 launchd 상주 서비스가 파일에 접근하다 `Operation not permitted`로 막힐 수 있습니다(터미널에서 직접 실행할 때는 보통 문제없음). 서비스가 로그에서 권한 오류를 내면 ①시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한에 `.venv/bin/python`(실제 파이썬 실행 파일)을 추가하거나 ②프로젝트를 `~/research-lab` 처럼 보호되지 않는 위치로 옮기세요. colima(도커)도 이 폴더를 마운트하므로 같은 점검이 필요할 수 있습니다.
- 에이전트는 사람이 아닙니다. 보고서의 해석과 통계는 검증 단계를 거치지만 **최종 판단과 논문에 쓰기 전 확인은 연구자의 몫**입니다.

## 에이전트 추가·조정

- **전문가(자문+해석 참여) 추가** 예: 통계·실험설계 전문가 → `lab/tools.py`의 `CONSULTANTS`에 키 추가 → `lab/agents.py`의 `ROLE_META`, 프롬프트(`LINGUIST`와 같은 형식, `_CONSULT_COMMON` 포함)와 `ROLE_PROMPTS` 추가 → `DIRECTOR` 프롬프트의 명단 갱신. 자문·해석·수정 라운드에는 자동으로 참여합니다.
- 단계 순서나 승인 조건은 `lab/pipeline.py`(`_phase_*`, `_gate_reasons`), 공통 연구 규칙은 `LAB_RULES.md`에서 바꿉니다.
- 모델은 `.env`의 `MODEL_*`로 역할군별로 바꿉니다.

테스트는 LLM 응답을 미리 짠 가짜 클라이언트로 대체해 접수→완료 전 과정, 승인 게이트, 검증→수정 순환, 예산 일시정지, 재시작 복구, 권한 제한을 확인합니다. 실제 Anthropic·디스코드·도커 연결은 `--check`로 점검합니다.

연구실장 외 9명이 각자 봇으로 서버 멤버 목록에 뜨고, 연구자와 따로 대화합니다. 토큰이 없는 팀원은 건너뛰므로 일부만 켜도 됩니다.

| 역할 | 봇 이름 |
|---|---|
| 언어학 전문가 | Linguist |
| 인지·뇌과학 연구원 | Cognitive Scientist |
| 언어모델 연구원 | LM Researcher |
| 통계·실험설계 전문가 | Statistician |
| 코퍼스·데이터 전문가 | Corpus & Data Engineer |
| 실험 실무 담당 | Experiment Coordinator |
| 백엔드 개발자 | Backend Developer |
| 서류화·보고 담당 | Report Writer |
| 검증 테스트 담당 | QA Verifier |

**만들기** — Developer Portal 에서 위 이름으로 앱을 만들고, 앱마다 Bot → Reset Token. 팀원 봇은 멘션·DM으로만 대화하므로 Message Content Intent가 필요하지 않습니다. 연구실장 봇은 실험 요청을 직접 읽으므로 이 Intent를 켜야 합니다.
그다음 `python3 scripts/add_bot_tokens.py` 를 실행해 토큰을 붙여넣으면(화면에 안 보임) `.env` 에 저장되고 서버 초대 링크가 출력됩니다.
연구실장 봇은 네 공용 채널을 시작할 때 확인하고, 없으면 만듭니다('채널 관리' 권한이 있을 때).

**말 거는 법** — 실험 스레드나 `#봇점검`에서 `@Statistician`처럼 멘션 · DM.
다른 팀원만 멘션하면 연구실장은 끼어들지 않습니다. 봇끼리는 서로 대답하지 않습니다.
팀원 봇은 읽기 도구(현황·실험 파일·연구노트)만 쓰고, 접수·중단·승인은 하지 않습니다.

**성능고도화 채널** — 에이전트 성능 향상을 위한 학습·테스트 리포트는 연구 진행과 무관하므로 `#성능고도화`(`PERF_CHANNEL`)에만 올립니다. `python3 scripts/report_test_results.py` 가 각 팀원 이름으로 결과를 올립니다.

**봇점검 채널** — 접속, 멘션 응답, 권한, 첨부 및 개발 중 임시 대화를 시험합니다. 연구실장도 이 채널에서 멘션하면 답합니다. 정식 학습·평가 결과는 `#성능고도화`에 남깁니다.

**결과물 채널** — `#results-산출물`에 완료된 실험의 최종 보고서와 파일만 모읍니다. 진행 맥락과 최종 요약은 해당 실험 스레드에도 남습니다.

**진행 알림** — 자문·해석 메모, 계획 확정, 구현·실행, 보고서, 검증 결과가 담당 팀원 이름으로 실험 스레드에 올라옵니다.
